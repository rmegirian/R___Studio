Contributing to the Staff Resource Library

The instructions below describe a standard Git workflow for how to add or update pages in the AAGI Staff Resource Library.

All staff are encouraged to contribute.

Before you begin

you will need:

  • Git installed on your computer
  • Quarto installed if you want to view the site locally while working on it

Step 1. Cloning the repository to your computer

\(\color{#ec8525}{\text{Note:}}\) you only need to complete this first step once

  • Mac: Open the application named Terminal
  • Windows: Open the application named GitBash

When the terminal opens, it shows your current directory. If this is not where you want to save the project, you can move to a different folder using the cd command.

One simple method is:

  1. Open File Explorer (Windows) or Finder (Mac)
  2. Navigate to the folder where you want to store the project
  3. Copy the full path from the path bar
  4. Use that path inside quotation marks after the cd command

This ensures you move directly to the correct folder, even when the path contains spaces.

Example:


cd "C:\Users\yourcurtinlogin\Documents"

Once you’re inside the folder where you want to save the project, run:


git clone https://github.com/CCDM-CBADA/AAGIStaffResourceLibrary.git

This creates a new folder named 📁AAGIStaffResourceLibrary inside the location you chose.

Move into that folder using the terminal:


cd AAGIStaffResourceLibrary

You now have the AAGI Staff Resource Library website files on your computer, and you are currently inside the main branch of the project.

Step 2. Creating a branch for your changes

The next thing you do, before you begin editing any files, is create a branch for your work.

\(\color{#ec8525}{\text{Note:}}\) If you have just cloned the repository to your computer, your main branch is already up to date and you are ready to create a branch for your edits. If you first cloned the repository on an earlier day, complete Step 3b. Update your main branch before continuing with this step

All edits should be made inside a separate branch. This protects the main branch and keeps each set of changes organised. A branch is not a new copy of the project. It is a labelled workspace where a related group of changes is kept together.

Branch names

Choose a name that describes the edits or additions you are making.

For example:

  • add-analysing-count-data-page
  • update-visual-assets
  • fix-typo-on-home-page
  • add-new-useful-functions-section

It is good practice to use separate branches for unrelated tasks. This keeps each change clear and easier to review and allows you to finish one branch and submit it even if other branches are not yet complete.

Create your branch

In the terminal, once you’ve navigated to the AAGIStaffResourceLibrary folder, run:


git checkout -b name-of-your-branch

This command does the following:

  • checkout tells Git you want to switch branches
  • -b tells Git to create a new branch
  • name-of-your-branch is the name of your new working branch.

For example:


git checkout -b add-analysing-count-data-page

Step 3. Updating main and keeping branches current

\(\color{#ec8525}{\text{Note:}}\) Whichever branch you are on in the terminal is where your edits will be saved. Before you open any project files in your editor, always make sure you are on the correct branch and that it contains the most up-to-date version of the project

Step 3a. Check and select your branch

check which branch you’re on:


git branch

The branch with an asterisk next to it is the branch you are on.

To switch to a different branch:


git checkout branch-name

Step 3b. Update your main branch

If there’s any chance that your main branch isn’t up-to-date with the version on GitHub, you should update your main branch.

Navigate to the project folder if you are not already there:


cd "path to AAGIStaffResourceLibrary"

Make sure you’re on the ‘main’ branch of the project:


git checkout main

Pull the newest version from GitHub:


git pull origin main

Your main branch now contains the most recent version of the site.

Step 3c. Bring the newest changes from main into your working branch

Switch to your working branch:


git checkout your-branch-name

Merge the updates from the ‘main’ branch:


git merge main

If there are conflicts Git will show them and you can resolve them.

If there are no conflicts, the merge will happen silently.

Once this is done, your working branch is ready to use.

Step 4. Opening the project and making changes

Once you are on the correct branch in the terminal and it’s up-to-date, you can open your local project folder 📁AAGIStaffResourceLibrary in your chosen editor and begin making your changes to the AAGI Staff Resource Library.

Common ways to open the project:

  • Open Finder/File Explorer and double click the file named AAGIStaffResourceLibrary.Rproj to open the project in RStudio
  • Open the 📁AAGIStaffResourceLibrary folder directly in VS Code or any other editor you prefer.

Once the project is open, you can Add new pages, edit existing pages, and Preview your changes. The sections below explain each of these tasks.

Add new pages

  1. In your editor, open the folder named pages
  2. Choose the most appropriate subfolder for your new page, or create a new subfolder
  3. Create a new file with the file extension .qmd inside this folder
  4. Add a short title at the top of the file, then write your content and save the file
  5. Open the file named _quarto.yml in the main project folder
  6. Find the correct section, or create a new one, in the sidebar navigation
  7. Add a new entry for your page that matches the file path of your new .qmd file

Adding the new entry to the .yml is essential because this is what links your new page to the website and places it in the site navigation.

Edit existing pages

  1. Open the .qmd file you want to edit
  2. Make your changes and save
  3. If you rename or move a page, update the file named _quarto.yml so that the page is still linked to the website and the site navigation continues to work.

Preview your changes

There are two ways to preview the site:

  • Option 1: Open index.qmd and use the render button.
  • Option 2: In the terminal, run the command:

quarto preview

This should open a live version of the website that updates whenever you save a .qmd file.

Check that:

  • Your new or edited page appears in the navbar
  • The link in the navbar takes you to the correct page
  • Your changes display as expected

Step 5. Saving your progress through commits

\(\color{#ec8525}{\text{Note:}}\) It’s good practice to save your progress regularly while working on a branch. You can do this by creating commits. A commit creates a checkpoint or snapshot of your progress. It is essential to commit your changes before moving between branches. A commit doesn’t send anything to GitHub. It only stores a safe copy of your work on your computer

You should make a commit when you:

  • Have finished a small task during a work session
  • Are finishing your work for the day
  • Want to switch to a different branch

To save a checkpoint, open the terminal, make sure you are inside your project folder and on your working branch, and run:


git status
git add .
git commit -m "describe progress on this branch"

This creates a snapshot of the changes you have saved in your files. The snapshot stays on your computer and belongs to your working branch.

You can make as many commits as you like. A commit doesn’t need to be perfect. It’s simply a record of where you’re up to.

If your edits aren’t finished yet and you do not want to share anything on GitHub, you can stop after this step. Your progress is now safely stored on your computer.

Step 6. Saving progress on GitHub by pushing

\(\color{#ec8525}{\text{Note:}}\) Pushing sends all of the commits on your branch to GitHub. If you haven’t created any commits, there’s nothing to push and this step can’t be completed

Push your branch to GitHub if:

  • you want your progress backed up somewhere other than your computer
  • you want to be able to continue your work on a different computer
  • your work on this branch is complete and you are preparing for Step 7. Create a pull request to have your work reviewed

To push your branch, open the terminal, make sure you’re inside your project folder and on your working branch, and run:


git push origin name-of-your-branch

Once this command finishes, your branch will appear in the branch list on GitHub. Your work is now stored both on your computer and on GitHub.

You can continue making new commits and pushing them to update your branch on GitHub until you’re ready to make a pull request.

If you want to continue working on this branch without merging your changes into the main site yet, you can stop after this step.

If your work on this branch is complete and ready to become part of the main site, continue to Step 7.

Step 7. Create a pull request to have your work reviewed

\(\color{#ec8525}{\text{Note:}}\) To create a pull request, your branch must exist on GitHub. This means that if you haven’t already, you must complete Step 5. Saving your progress through commits & Step 6. Pushing to GitHub before continuing

When your work on this branch is complete and you’re ready for your changes to be added to the official site, you create a pull request. A pull request asks a maintainer to review your branch, compare your changes with the main branch, and if everything is correct, merge your work into the official site.

To create a pull request:

  1. Go to the repository on GitHub in your web browser
  2. Select your branch from the branch dropdown menu
  3. GitHub will show whether your branch can be merged
  4. Click the button to create a pull request
  5. Add a short explanation of the changes you made
  6. Submit the pull request

A maintainer will review your work and, if everything is correct, merge it into the main branch. After the merge, your changes become part of the official website.

If the maintainer requests edits, you can continue working in the same branch on your computer. Each time you run git add, git commit, and git push, the pull request will update automatically.

Optional Extras

These optional steps are for staff who feel comfortable with the basic workflow and want to learn how to keep their branches tidy, solve simple problems, and understand what to do when Git asks questions.

Deleting old branches from your computer

After your branch has been merged into the main branch on GitHub, you no longer need that branch on your computer. Removing old branches keeps your workspace tidy and helps prevent mistakes.

To list your branches and see which ones have already been merged:


git branch --merged

The branches without an asterisk have already been merged.

To delete an old branch from your computer:


git branch -d name-of-branch

This doesn’t delete the branch from GitHub, it only removes it from your computer.

If Git warns that the branch is not fully merged, stop and make sure it’s been merged on GitHub before deleting it.

Deleting old branches from GitHub

Once a pull request has been merged, GitHub will usually show a button that says something like delete branch.

Clicking this button safely deletes the branch from GitHub.

If you want to delete a branch manually:

  1. Go to the repository on GitHub

  2. Open the tab named branches

  3. Find the branch you want to delete

  4. Select delete

Deleting a branch on GitHub doesn’t affect your work on your computer.

Handling simple merge conflicts

A merge conflict happens when two people change the same part of a file in different ways. Git can’t choose which changes to prioritise for you, so it asks you to decide.

When a conflict occurs, Git will:

  • Stop the merge
  • Tell you which file contains the conflict
  • Mark the exact lines that need attention

Inside the file you will see markers that look like this:

Tip

<<<<<<< HEAD

your changes

=======

changes from main

>>>>>>> main

To fix a conflict:

  1. Open the file in your editor

  2. Choose which content is correct

  3. Delete the content you don’t want

  4. Delete all of the conflict markers

  5. Save the file

Add and commit the fixed file:

git add . git commit -m "fix merge conflict"

After this, the merge is complete.

Troubleshooting

Below are some common issues and simple solutions.

My terminal says my branch is ahead or behind main

This means the two branches have different commits.
Return to Step 3. Updating main and keeping branches current and update your main branch, then merge main into your working branch.

I accidentally made changes on the main branch

Do not pull from GitHub.
Make a new branch to protect your work:

git checkout -b new branch name

Your work is now safe.
Return to Step 3. Updating main and keeping branches current.

Git says there’s nothing to commit

You may not have saved the file in your editor.
Save your changes and try again.

Git says there’s nothing to push

You haven’t made a commit yet.
Complete [Step 5. Saving progress locally through commits] first.

My site preview doesn’t update

Make sure you saved the .qmd file.
Make sure you updated the navigation file if you created or renamed a page.
Restart the preview if needed.

I pushed the wrong changes

If the pull request has not been reviewed yet, simply keep making commits and pushing.
Your pull request will update automatically.
